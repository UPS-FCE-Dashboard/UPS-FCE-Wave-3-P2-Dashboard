        Sub-task boxes are consolidated into five stages. Each stage’s color comes from its current open Jira sub-task (the first one in that stage that is not Completed, Done, or Withdrawn): delayed if that sub-task’s Planned Complete Date is before today, on track if it is still open and not past due. Withdrawn is closed, the same as Completed, and is not a blocker. Expand a RICE item for the full sub-task list and associated change requests.

        How to read the P2 RICE Tracker

        Five stages: Functional Design (functional design, review, approval, FSD handoff) · Tech Design (technical analysis, technical design, review, approval, build) · Unit Testing · Functional Testing (handoff, functional testing, defect resolution) · Code Promotion (code promotion, update technical design). Dual-track labels such as Coupa IH / ERPP roll into the same stage.

        On track vs delayed: a stage that has not started stays cream. A fully completed stage uses the completed color. Once a stage has started, its color is taken only from the current open sub-task in that stage — delayed if that sub-task is past its Planned Complete Date, on track if it is still within date, brown if it is Blocked. Completed, Done, and Withdrawn are closed, so a Withdrawn step is skipped and the stage advances to the next incomplete step.

        P2 RICE at risk: the list includes every item that is not Complete, and Complete items that still have at least one open CR. Complete items with no open CR are omitted.

        Columns: RICE item, Jira status (current open sub-task / parent status), the five stages, and open CRs. The last count is linked change requests that still have an open defect — expand the row to see those CRs first.

        How to read the P2 Testing Execution tab / About this data

        Scope: Jira test cases for Release 1 - P2 across Source to Pay, Acquire to Retire, and Plan to Report. Exact Jira filter: TBC

        Executed: a test case in Passed, Failed, Retest or Withdrawn status. This matches the Wave 2B daily status. Confirm for P2 Counting Withdrawn as executed raises % Executed.

        Overall execution: Executed ÷ all in-scope test cases. Not executed is Open, In Progress, Blocked and On Hold.

        Overdue: not executed, with a due date before the snapshot date. Ready to test now is overdue and Open or In Progress. Blocked / on hold is overdue and Blocked or On Hold.

        Key blockers: the open defects linked to the most blocked or on-hold test cases.

        Critical and High defects: open defects with severity Critical or High. Past due means the Jira due date is before the snapshot date.

        Defects: Total is every defect to date. Open is every defect not Resolved, including Ready for Retest. Confirm for P2

        Overall status: On track when executed is at least 95% of the test cases expected by the snapshot date. Behind plan when it is lower.

        How to read this dashboard / About this data

        Conversion objects and subtasks: Jira Conversion Execution subtasks for Release 1 - P2. Withdrawn objects are excluded. The Executive Summary uses Data Conversion records only; Release 1 - P2 Prep never contributes to these metrics.

        Defects: open Jira defects labeled conversion that have fixVersion Wave 3 (including functional-team defects) or component Release 1 and Test Cycle P2 (including defects with no fix version). On Hold defects remain in the open count and are labeled On Hold; they are not blockers.

        Risk: any past-due conversion subtask, plus any past-due open defect of Critical or High severity. Medium, Low, and On Hold items stay on the dashboard but are not raised as Risks. Recon-related work is excluded from Risks and Blockers because it does not gate downstream activity.

        Blocker: only an item whose Jira status is exactly Blocked. The dashboard does not infer blockers, and On Hold never counts as Blocked.

        Key blocker / issue: an overdue Extract-through-Load subtask with a Jira predecessor link to downstream work. The section lists those linked items when they exist and shows a readiness note when they do not.

        % of Subtasks Complete: completed conversion subtasks ÷ all in-scope conversion subtasks. It is not an average of object statuses.

        Dates and freshness: defect Target Retest comes directly from Jira Due Date. Dates are being refreshed by the team. The timestamp above records the latest Jira refresh.

        System of record: Jira remains authoritative. This is a read-only daily snapshot; records cannot be edited in the dashboard.

        Out of scope: Jira Action Items are not included. This dashboard contains only Conversion Execution subtasks and open conversion defects in the Wave 3 or Release 1 P2 scope above.
